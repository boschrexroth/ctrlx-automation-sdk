# AGENTS.md

Guidance for AI coding agents working in this directory.

## What this directory is

`samples-node/` contains the Node.js/TypeScript sample applications
published as part of the ctrlX AUTOMATION SDK (see `public/AGENTS.md` and
the repository root `AGENTS.md` for how this fits into the overall build
pipeline). These samples are edited in place here — this folder is the source of truth for Node.js sample code.

`README.md` is the index of all samples. `build-node-app.sh` at this level
is a shared helper for building/packaging the Node.js samples.

## Layout per sample

Each `<sample-name>/` (e.g. `datalayer.provider.simple`) generally contains:
- `package.json` / `package-lock.json` — npm project definition; the
  `dependencies` reference the SDK's own packaged tarballs via
  `file:../../nodejs/ctrlx-datalayer-*.tgz` (not the public npm registry).
- `src/` — TypeScript source; `tsconfig.json` configures the compiler.
- `dist/` — compiled JavaScript output (generated by `npm run tsc`, do not
  hand-edit).
- `fbs/` / (compiled) `bfbs/` under `src/` — FlatBuffers schema sources;
  copied into `dist/bfbs` via the `copy-bfbs` npm script.
- `build-fbs.sh` — generates FlatBuffers bindings.
- `build-snap-amd64.sh` / `build-snap-arm64.sh` — package the built
  artifact as a Snap.
- `snap/` — Snapcraft packaging manifest.
- `docs/` — sample-specific documentation assets.

Follow the naming pattern `datalayer.<role>.<variant>` (e.g.
`datalayer.client.browse`, `datalayer.provider.wildcard`) for new
Datalayer samples, matching the conventions used across the other
`samples-<lang>/` folders. Mirror the existing per-sample layout when
adding a new one.

## Adding or changing a sample

- Add new samples to the top-level `README.md` index and to
  `../samples.md` if applicable.
- Keep the `ctrlx-datalayer*` dependency versions in `package.json`
  pointing at the local `../../nodejs/*.tgz` packages produced by the
  build, not a public registry version — update the version/filename
  together with the corresponding nodejs SDK package bump.
- npm audit for these samples runs in CI (`private/make/audit_node.sh`)
  only when `$BRANCH_NAME` is set; not required for local changes.

## Validation

There is no separate unit test suite — validate changes by installing and
building the affected sample:
```bash
cd <sample-name>
npm install
npm run prepare   # runs copy-bfbs + tsc
```
For Snap packaging changes, run `build-snap-amd64.sh` (or `-arm64.sh`),
which requires the ctrlX AUTOMATION App Build Environment / Snapcraft
tooling.
